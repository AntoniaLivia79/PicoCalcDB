# Extending the code

Where to make the most likely changes, and what has to change together.

## Changing limits

The limits are constants at the top of `dbcore.bas` (`IX_MAX`, `SX_MAX`, `IX_KLEN`, `SX_SLOTS`, `SX_PW`), `dbstore.bas` (`MT_MAX`, `ST_CATMAX`), `dbquery.bas` (`TK_MAX`, `QN_MAX`, `QF_MAX`, `QV_LEN`, `QNV_LEN`) and `dbexec.bas` (`EX_OUTMAX`). Everything is sized from them. Points to watch:

- **`IX_MAX` and `SX_MAX` dominate memory** ([Architecture](Architecture.md#configuration-and-memory)). Raising them on a Pico 2 is reasonable; on an RP2040, lower them if memory is short.
- **`IX_KLEN` also limits `_id`s in saved `.idx` files.** Existing data with longer ids would be rejected.
- **`SX_PW` changes the encoded index keys.** Secondary indexes are rebuilt on every open, so no file format changes.
- **`RC_MAXLEN` cannot usefully be raised**: it is MMBasic's string limit.

## A new query statement

1. **Parser (`dbquery.bas`):** add the keyword to `QRES$` and to the command list checked in `QParse%`, then add a `CASE` that calls a new `Q…` SUB to fill in the plan. Reuse the existing plan variables where they fit (`QCol$`, `QFld$()`, `QVal$()`), and add new globals with the `Q` prefix if not.
2. **Executor (`dbexec.bas`):** add a `CASE` to `ExRun%` that does the work through the storage engine, sets `ExKind$` and `ExMsg$`, and sets `ExErr$` on failure.
3. **Help:** add a topic to the help file and to the [user guide](../../user/dbapp-user-guide.md). In the repository, the help topics are generated by `tools/make_help.py` into `sdcard/db/help/dbhelp.jsonl`.

The library picks the statement up automatically, because `DbQuery%` is `ExRun%`.

## A new comparison operator

1. Add a `QO_…` constant below `QO_AND` (operators below 20 are leaves).
2. Recognise it in `QLeaf%`, and give it a name in `QOpName$`. If it should also work in `DbFind%`, add it to the operator list there.
3. Evaluate it in `ExLeaf%`.
4. If an index can help with it, handle it in `ExPlanPath` and `SxRange`/`IxRange`. Remember that secondary ranges must be conservative: the executor re-checks every candidate, but it can't recover a record the range left out.

## A new view in the explorer

1. Add a `UV_…` constant and enlarge `UiSel%()`/`UiTop%()` if needed.
2. Teach `UiCount%`, `UiRowText$`, `UiTitle$` and `UiHints$` about it. Drawing, scrolling and navigation then work automatically.
3. Add its key handling as a `CASE` in `UiKey`, in a new `UiKey…` SUB.
4. Set `UiFull% = 1` whenever its contents change, so `UiPaint` redraws.

## A different display

Replace `dbhal.bas`. Keep the four routines, `HalW%`/`HalH%` and the style numbers 0–7. `HalText` must draw a string of any length up to `HalW%` at a character position; the GUI always draws full-width lines.

## A new API routine

Follow the pattern of the existing ones: name it `Db…`, do the work through engine routines, and report through `DbOk%` so that `DbErr$()` is always set. Never return more than 255 characters from a string function. If the routine changes data in the open collection, remember that any result list from `DbQuery%` still refers to the old versions.

## Things not to change lightly

- **The append-only file format** is what makes crash recovery, stable offsets and snapshot result lists possible.
- **The order of checks in `StWrite%`.** Capacity is checked before appending, so the file and the index cannot get out of step.
- **Conservative secondary ranges in `SxRange`.** Tightening them can silently lose matching records.
