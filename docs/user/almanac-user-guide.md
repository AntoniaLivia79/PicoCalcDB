# Almanac for the PicoCalc

A day-by-day almanac browser for the PicoCalc. It loads almanac entries from a CSV file into a PicoCalc DB collection, then lets you browse them by day and search their details.

## Installing

Copy two files to the root of the SD card:

| File | What it is |
|---|---|
| `almanac_app.bas` | The program (the DB library and display code are included); in the repository's `dist/` folder |
| `almanac.csv` | The almanac data (the supplied file, 1 Oct 2026 to 31 Dec 2027); in the repository's `sdcard/` folder |

Then, at the `>` prompt:

```
DRIVE "B:"
RUN "almanac_app.bas"
```

The first time, choose **1 Maintain database**, then **C**, to load the CSV. This takes a little while; the message line shows progress.

## The main menu

| Key | Does |
|---|---|
| **1** | Maintain database |
| **2** | Browse the almanac by day |
| **3** | Search the almanac |
| **Esc** | Quit |

Below the menu you can see the date range and number of records loaded.

## 1. Maintain database

This screen shows whether `B:/almanac.csv` is present, and what is loaded: number of records, first and last day, when it was loaded and from which file.

| Key | Does |
|---|---|
| **C** | Create the collection from the CSV (when none exists yet) |
| **R** | Drop and recreate it from the CSV. Asks first, because it replaces all data |
| **Esc** | Back to the menu |

After a load, the message line says how many rows were stored and how many were skipped, with the reason for the last skipped row.

## 2. Browse the almanac

Browsing opens on today's date if the PicoCalc clock is within the almanac, and on its first day otherwise. Each entry for the day is shown with:
- its category (yellow);
- the event and its detail;
- any saying or lore, in quotes;
- the place and how certain the information is (grey).

| Key | Does |
|---|---|
| **Left / Right** | Previous / next day |
| **+ / -** (or PgDn / PgUp) | 30 days forward / back |
| **Home / End** | First / last day of the almanac |
| **Up / Down** | Scroll, when a day has more than one screen of entries |
| **G** | Go to a date: type it as `YYYY-MM-DD` and press Enter |
| **T** | Today (if the clock is set and today is in the almanac) |
| **Esc** | Back |

## 3. Search the almanac

Type one or more words and press Enter. The search looks in the **detail** of every entry and lists those containing **all** the words, ignoring upper/lower case. For example, `full moon` finds details containing both "full" and "moon".

Each result shows its date and detail. Use **Up / Down** to choose one and **Enter** to open that day; **Esc** returns to the results, and **Esc** again to the menu. At most 300 results are listed; add another word to narrow the search.

## The CSV file

The first line must name the columns. They can be in any order:

| Column | |
|---|---|
| `date` | **Required.** `YYYY-MM-DD` |
| `event` | **Required** |
| `detail` | **Required.** This is the column the search uses |
| `category`, `saying_or_lore`, `place`, `certainty` | Optional |
| `weekday` | Ignored: the program works out the weekday from the date |

- Values containing commas go in double quotes; a double quote inside them is written twice (`""`).
- The file can be saved from a spreadsheet (with or without a UTF-8 byte-order mark, Windows or Unix line endings).
- Each line must be at most 255 characters. Longer lines, rows with an invalid date and rows with an unclosed quote are skipped and counted.
- Use plain ASCII characters; others may not display correctly.
- Several rows may share a date; they are shown in file order.

## How the data is stored

Data is stored in the collection `almanac` in `B:/db/`, so you can also open it in the PicoCalc DB explorer, or read it from your own programs with the DB library. Each CSV row becomes one record:

```
{"_id":"2026-10-01.02","cat":"Month","event":"October - ...","detail":"Bede's ...",
 "lore":"Good October, ...","place":"England","cert":"fixed"}
```

- The `_id` is the date plus a sequence number, so records sort by date.
- If a row's saying would make the record longer than 255 characters, the saying is stored in a companion record with the same `_id` plus `L` (31 rows in the supplied file).
- One collection holds up to 1,000 records. The supplied file needs 885, so the program can take roughly 17 months of data at this density. If a load stops with `collection full`, split the CSV.
